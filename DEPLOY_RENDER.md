# Free deployment: backend on Render (free), database on Neon (free), frontend on Vercel

Zero hosting cost. The NestJS + Prisma backend is deployed unchanged; `render.yaml` (repo root) describes it.
The Vercel frontend is only reconfigured (one environment variable).

| Piece | Where | Cost |
|---|---|---|
| React frontend | Vercel (already deployed) | free |
| NestJS backend | Render web service, `plan: free` | free |
| PostgreSQL | Neon (create it yourself, paste the URL) | free |
| Gemini | Google AI key, server-side only | your existing key |

## Read this first: what the free tier does NOT give you

1. **Uploaded files are temporary.** A free Render service has no persistent disk. Files are stored in
   `/tmp/uploads` and disappear whenever the service restarts, redeploys or spins down after ~15 minutes without traffic.
   - **Survives (in PostgreSQL):** accounts, applicants, extracted text, claims and evidence, document runs, evaluations,
     journey state, agent actions, clarifications. A document that was **already processed** keeps all its evidence
     and its status.
   - **Lost:** the original file. The backend reads a file only while processing it, so a document that was uploaded
     but **not yet processed** (or that you force re-scan) after a restart fails with a clear message: *"The uploaded
     file is no longer available on the server (temporary storage was reset). Please upload it again."* Earlier evidence is kept.
   - **For the demo:** upload and process in one sitting, and open the site a minute before presenting. If a
     restart happens in between, re-upload the affected document.
2. **Cold starts.** The free service sleeps after ~15 minutes idle; the first request then takes roughly 30-60 s
   (start + migrations). Neon also suspends an idle free database and wakes it on the next query. Warm both up before presenting.
3. **Need files to persist?** That requires a paid Render disk or external object storage, which is a code change; it is not part of this setup.

## 1. Create the Neon database (free)

1. neon.tech → new project → pick a region near Render's (`oregon` ≈ US West).
2. Copy the **direct** connection string (host **without** `-pooler`). Migrations should not run through the pooler.
3. It looks like `postgresql://USER:PASSWORD@HOST/neondb?sslmode=require&channel_binding=require`.
   **Delete `&channel_binding=require`**, so the final value is `...neondb?sslmode=require`. (The `pg` driver does not
   implement channel binding. `sslmode=require` is supported; the driver may print a harmless deprecation warning.)
4. Keep this string private; it goes only into Render's `DATABASE_URL`.

## 2. Create the Render service (Blueprint)

1. Commit/push `render.yaml` on `integration/frontend-backend` first.
2. Render → **New → Blueprint** → connect `ImpactX26/noobsabhaeducaro`, branch `integration/frontend-backend`.
3. When prompted, paste:
   - `DATABASE_URL` = the Neon string from step 1
   - `GEMINI_API_KEY` = your Gemini key
4. Apply. Everything else is preset by the Blueprint (the plan must read **Free**; no disk, no database).

### Commands (already in `render.yaml`)
- Build: `npm ci --include=dev && npx prisma generate && npm run build`
- Start: `npx prisma migrate deploy && npm run start:prod` (applies only pending committed migrations; never resets data)
- Health check: `GET /health` (200 when the database answers, 503 when it does not). Render provides `PORT`.
- Node: 24

### Environment variables (Render → service `sieg-backend`)
| Variable | Value | Source |
|---|---|---|
| `DATABASE_URL` | Neon string, `?sslmode=require`, no `channel_binding` | you paste |
| `GEMINI_API_KEY` | your key | you paste (server-side only) |
| `JWT_SECRET` | random, ≥ 32 characters | generated by Render |
| `JWT_EXPIRES_IN` | `8h` | preset |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | preset |
| `UPLOAD_DIR` | `/tmp/uploads` | preset (temporary) |
| `CORS_ORIGINS` | `https://noobsabhaeducaro.vercel.app` | preset; comma-separate extra origins |
| `NODE_VERSION` | `24` | preset |
| `PORT` | provided by Render | automatic |

## 3. Check the backend

Open `https://<service>.onrender.com/health` (allow ~1 minute on a cold start). Expect:
`{"status":"ok","db":"up", ...}`. In the Render deploy log you should see the migrations applied
(first deploy: 5 migrations). API docs: `/docs`.

## 4. Point Vercel at it

Vercel → project `noobsabhaeducaro` → **Settings → Environment Variables**:
- `VITE_API_BASE_URL` = `https://<service>.onrender.com` (Production; no trailing slash).
- Do **not** add `GEMINI_API_KEY` or any secret to Vercel. `VITE_` variables are public in the browser bundle.

It is read at build time: **Deployments → … → Redeploy** afterwards. Then open the site, register a new account
(local demo accounts do not exist in the hosted database), upload, process, and check the journey.

## Notes
- If you open the frontend from another origin (a Vercel preview URL), add it to `CORS_ORIGINS` (comma-separated).
- Free Neon/Render limits (hours, storage, expiry) change over time; check their current terms before relying on them.
- Requirements are DEMO configuration, not official criteria (unchanged).
