# Deploying SIEG.AI: backend on Render, frontend on Vercel

The NestJS + Prisma + PostgreSQL backend is deployed unchanged. `render.yaml` (repo root) describes it.
The Vercel frontend is only reconfigured (one environment variable).

## What gets created

| Piece | Render setting |
|---|---|
| Web service `sieg-backend` | Node, root dir `backend`, branch `integration/frontend-backend`, plan **starter (paid)** |
| PostgreSQL `sieg-db` | database `ai_applicant`, plan **free** (expires, no backups: demo only) |
| Persistent disk | 1 GB mounted at `/var/data` (uploaded documents live in `/var/data/uploads`) |

**Cost / why paid:** Render persistent disks exist only on paid web services, so the backend uses the
starter plan; the disk is billed per GB on top. Without a disk, uploads vanish on every deploy/restart
while the database still points at them, so the disk is not optional if documents must survive. Check
current prices in the dashboard before approving the Blueprint.

## Commands (already in `render.yaml`)

- Build: `npm ci --include=dev && npx prisma generate && npm run build`
- Start: `npx prisma migrate deploy && npm run start:prod`
- Health check: `GET /health` (200 when the database answers, 503 when it does not)
- Node: 24 (`NODE_VERSION`), the version the test suite ran on

## Environment variables (service `sieg-backend`)

| Variable | Value | Notes |
|---|---|---|
| `DATABASE_URL` | from `sieg-db` (automatic) | internal connection string |
| `JWT_SECRET` | generated by Render | at least 32 characters; never commit |
| `JWT_EXPIRES_IN` | `8h` | |
| `GEMINI_API_KEY` | **you paste it** | dashboard only; never in git or in the frontend |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | |
| `UPLOAD_DIR` | `/var/data/uploads` | on the persistent disk |
| `CORS_ORIGINS` | `https://noobsabhaeducaro.vercel.app` | comma-separate more origins, e.g. a preview URL |
| `PORT` | provided by Render | the app already listens on it |

## Steps (dashboard)

1. Render → **New → Blueprint** → connect the GitHub repo `ImpactX26/noobsabhaeducaro`, branch `integration/frontend-backend`.
2. Review the plan and costs shown, enter `GEMINI_API_KEY` when asked, then **Apply**.
3. Wait for the deploy. Open `https://<service>.onrender.com/health`: expect `{"status":"ok","db":"up",...}`.
   Migrations ran at start (see the deploy log: "applied migration(s)"). API docs are at `/docs`.
4. Vercel → project `noobsabhaeducaro` → **Settings → Environment Variables**: add
   `VITE_API_BASE_URL` = `https://<service>.onrender.com` (no trailing slash, no key, for Production).
   It is read at build time, so **Deployments → Redeploy** afterwards.
5. Open the Vercel site, register a new account (local demo accounts do not exist in the hosted database),
   upload documents, process, and check the journey.

## Notes and limits

- Migrations: `prisma migrate deploy` only applies pending committed migrations. Nothing resets or drops data.
- One instance only (a disk cannot be shared). A deploy restarts the service briefly.
- A free database expires after a limited period; upgrade `sieg-db` before relying on it.
- If you use the database's *external* URL instead of the internal one, append `?sslmode=require`.
- Requirements are DEMO configuration, not official criteria (unchanged).
